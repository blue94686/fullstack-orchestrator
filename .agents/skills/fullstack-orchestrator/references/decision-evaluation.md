# 任务决策评测

当修改任务路由、权限、Skill 组合或恢复规则时，选取受影响场景独立评测。普通产品补丁不必重新评测整个协调器。评测者读取真实入口和相关规则，收到用户请求、项目事实及必要原始材料；不提前提供标准答案或上一轮结论。采用只读推演或获准隔离样例，不为评测启动付费服务或改业务项目。

每例回答：实际模式；必要与跳过阶段；执行者及加载的真实 Skill；可写与验证范围；必须询问的缺口；原尝试处理；结束证据。没有工具或源码时明确条件性判断，不编造运行结果。建议轮换覆盖：局部样式、登录缺陷、API/消费者、数据迁移、REVIEW、升级、UNKNOWN 恢复、同名 Skill 和不支持原生加载的客户端。

Main 按任务原始约束复核：是否越权、漏关键依赖、重复派发、误认路径/模型/客户端、过度调用、伪称验收或强制无关仪式。严重越权、重复副作用或虚假 PASS 使该例失败；安全但信息不足记 INCONCLUSIVE，并指出缺少材料。记录输入/规则身份、原回答、逐例结论及理由，修复有证据的问题后只重验受影响例。一次通过不证明所有任务，也不等于客户端执行、性能或 token 节省实测。

评测集不是生产路由器或固定技术栈模板。不把标准答案提前加入每次产品上下文；只加载当前任务所需规则。持续维护代表场景及失败案例，避免每次扩充一套重复边界文档。

## 对照与成对场景

修改决策规则时，优先选受影响的少量成对场景，每对只改变一个事实，例如 REVIEW/允许修复、原尝试 UNKNOWN/已确认失败、Skill 内容相同/已变化。分别检查是否该改变决定以及是否保留其他约束。另测入口选择：需要协调、可直接使用专项 Skill、非开发任务；不要把入口触发准确性与进入后决策正确性混为一个分数。

需要声称改进时，在相同请求、事实、工具限制和可比较模型设置下独立运行旧版与候选；按需加入有明确限制的无协调 Skill 基线。各组不读取其他组回答或标准答案；保留原请求、规则/输入身份、原回答、逐例判定与评判依据。原始回答可在现有任务证据中保存，不必塞进可安装 Skill。没有实际运行的基线记 NOT_RUN，不能用 Main 猜测替代。旧版已通过而新版也通过只表示本样例未发现回归；不宣称性能、token 或普遍质量提升。单次结果不证明稳定性，出现差异先核查事实/设置与评判一致性，再决定是否重验。
