# 端到端闭环与退出、重入

本文件连接 scoped-development、boundary-strategy、operations、handoff 和 verification 的门槛，不替代它们，也不是已安装的调度器。按实际阶段读取对应规范，小任务以简短对话记录承载；长期/委派任务复用项目原生记录或 task-template.json。所有验收绑定具体需求、候选、环境和时间。

## 主链及交接门槛

| 环节 | Main 必须确定的输出 | 下一环节的准入/拒绝条件 |
|---|---|---|
| 接收与恢复 | 当前产品根目录、已有活动尝试、目标和已授权范围 | 根目录有歧义先询问；已有活动或未知尝试先核对，禁止重复提交 |
| 范围与影响 | 任务类型、task_mode、受影响与受保护模块、可写/验证范围、验收和不做事项 | 按 task-decision.md 决策；无真实产品任务只交付 Skill；必要依赖超出明确限制先解决范围冲突；重大未决目标留 DRAFT |
| 本地/上游参考 | 相关源码、适用 Skill；有收益时少量 GitHub 参考与来源 | 参考不授予执行权限；兼容性/许可证不清不复制采用 |
| 契约与拆分 | 业务流程、权限、API/事件/数据约束、依赖和责任人 | 仅冻结任务所需最小契约；设计不能决定服务端权限；依赖未通过不派发消费者 |
| 设计（适用时） | Stitch 资源身份、页面/动作/状态及 Main 接受记录 | 无可交接资源不能声称设计完成；普通设计检查 Main 决策，重大取舍才交用户 |
| 执行准备 | 路线、实际能力与权限、写入路径、输入版本、期限和结果位置 | 准备完整才 READY；缺能力已被观察则 BLOCKED；不得借路由规避限制 |
| 实现与收集 | 对应 attempt 的终态，或可核对且交付集合已关闭写入的受支持交付事件；真实文件/补丁和检查证据 | 提交仅一次；后端可按独立依赖并行；文件缺失或身份不符不得接受 |
| 集成 | Main 比较用户改动和基线后得到唯一最终候选 | 外部产物不能直接覆盖源码；冲突/契约漂移先处理，再跑受影响检查 |
| 验收 | 每项需求→产物→检查→证据→结果；Mock 与真实链分开 | 部分 PASS 不能关闭未满足需求；失败修复按同一问题最多两轮 |
| 交付 | 适用验收结论、运行方式、变更/限制、恢复方法和剩余事项 | 到达约定交付范围即结束；生产发布不从本地验收自动推导 |
| 发布（单独授权且适用） | 目标环境、候选身份、备份/迁移/回滚、烟测与观察窗口 | 授权绑定具体候选/环境；候选或重大影响变化后复核授权适用性；失败先按已授权恢复方案处理 |
| 归档与后续 | 结果、活动/未知任务、恢复点、下一行动和保留规则 | 后续需求重新做影响分析，不重新运行无关阶段；无人持续执行时不得承诺后台监控 |

受支持的交付事件可早于任务终态，仅允许收集、核验该交付集合；不能把仍运行的 attempt 标为 EXECUTION_DONE，也不解除禁止重复派发的限制。

前端实现先有必要契约和可用设计，后端实现不必等前端结束。已有设计可直接复用；无 UI 的任务跳过设计/前端。集成依赖双方所需输出，不依赖所有软件都被调用。

## 状态转换与异常分支

使用既有状态名，不新增与校验器不兼容的终态。状态表示当前控制步骤；execution/artifacts/integration 分别保留结果，检查失败不会擦除已观察到的执行终止。

多项目资源等待是独立调度说明，不新增生命周期状态。按 [本机协调](local-coordination.md) 保留活动分配：GUI 操作结束可释放其短授权，但后台执行仍保留开发/客户端/工作区资源；核对执行停止或交付集合关闭后才释放相关资源。不能根据超时、Main 退出或产物 PASS 自动释放其他仍被使用的资源。

| 当前情况 | 合法下一步 | 恢复条件 |
|---|---|---|
| DRAFT | READY、BLOCKED，或未提交且用户取消时 CANCELLED | 未填写仍为 DRAFT；已评估的外部阻止条件才 BLOCKED；取消记录未执行及原因 |
| READY | DISPATCHING，或未提交且用户取消时 CANCELLED | 再核对基线、授权、依赖和无重复活动尝试；只有确认未提交才能直接记录未执行取消 |
| DISPATCHING | RUNNING、已确认的 EXECUTION_DONE/FAILED 或 UNKNOWN_EXECUTION | 快速完成可跳过未观察到的 RUNNING；不得补造运行记录 |
| RUNNING | EXECUTION_DONE、FAILED、CANCEL_REQUESTED 或 UNKNOWN_EXECUTION | 等待超时不代表终止；未知先只读核对原任务 |
| UNKNOWN_EXECUTION | 依据证据恢复原实际状态 | 未知不能变成“无执行”；核对无果继续禁止重派，允许独立任务推进 |
| CANCEL_REQUESTED | CANCELLED 或核实后的实际状态 | 收到取消请求不等于任务已停；无取消接口记录限制，不强杀未知任务 |
| EXECUTION_DONE | ARTIFACT_VERIFIED 或 FAILED/BLOCKED | 缺文件、超范围、身份不符或检查失败时保留执行结果，拒绝产物接受 |
| ARTIFACT_VERIFIED | INTEGRATION_VERIFIED 或 FAILED/BLOCKED | 必须针对最终集成候选验证；局部任务仅检查其适用集成边界 |
| FAILED / CANCELLED | 保留本 attempt，按授权准备新 attempt | 明确终止及副作用、诊断原因、满足重试/修复上限；取消后遗留文件不自动接受 |
| BLOCKED | 消除原因后重新评估准备条件 | 有活动任务时以其真实状态为准；阻塞是依赖/检查结论，不伪装外部任务已停 |
| INTEGRATION_VERIFIED | 按约定交付，或进入另行授权的发布任务 | 新范围/受影响输入变化建立新修订/attempt，不覆盖历史 PASS |

直接本地任务不伪造外部提交步骤。无生产阶段可直接交付；纯文档/独立后端任务的“不适用”字段必须说明原因，而不是制造 E2E 证据。最终结论从需求映射和 outcomes 得出，不能只看 status 字符串。

具体产品任务的交付范围必须包含其适用的运行验证。外部软件、实际前端、业务 E2E、中断恢复和生产发布分别按任务影响启用。没有产品任务时可以保留 `NOT_TESTED`。有产品任务时，只有形成当前证据，或记录为 `NOT_APPLICABLE` 并说明原因，才能关闭对应门禁。

## 容易遗漏的闭环

- **用户中途变更/停止**：停止新依赖派发，记录已完成、运行中、未知及副作用；需取消时用支持的方式确认。新需求改变输入则建立新版本，确认旧尝试状态后再提交。用户仅问进度时回答后继续原任务。
- **错误目录或过期输入**：发现任务绑定错误、导出过期、分支漂移或目录授权过宽时停止受影响操作；检查实际写入和敏感暴露，保留必要脱敏证据。先修正归属和权限，不通过复制结果掩盖错误。
- **前端看似完成但仍为 Mock**：逐项映射页面动作到真实接口、认证/权限、业务/数据副作用和反馈；至少覆盖适用的失败/重试。仅样式修改验证原请求行为保持，不能强加后端重写。
- **通信与兼容**：契约变更检查所有实际消费者、版本兼容和旧数据；适用时覆盖超时、重复提交、并发写入、部分成功、取消/断连与重试，明确由哪层保证幂等和回滚。只有所需风险触发时启用这些专项。
- **无法独立复现检查**：保留外部自报但不升级验收；解释缺的环境/工具及下一步，可交付受限产物，不把剩余事项悄悄移出范围。
- **上线失败或验收后缺陷**：只在已授权范围内停止/恢复受影响发布；不可逆操作先确认影响。新缺陷建立与原候选关联的修复任务，复现、最小补丁、受影响回归，再独立验收，不篡改旧证据。
- **收尾仍有任务运行**：交付说明必须列出活动/未知任务和定位；未经授权不删除临时数据、不关闭用户服务、不回收仍使用的工作区。只在不影响恢复且符合保留规则时清理本次临时产物。
- **软件/Skill 更新或项目搬移**：按版本与受影响能力重验；缺少能力按 [skill-discovery.md](skill-discovery.md) 主动寻找并验证补齐；重新解析当前根目录和 shared/，不照搬旧绝对路径/权限。全局安装、跨对话发现及真实接入另计，不由项目 ZIP 更新自动成立。

## 最小收尾记录

在 Codex 一次说明：已实现内容、实际执行软件、适用验收及候选/环境、未验证或阻塞事项、用户改动保护情况、运行/恢复入口、仍在活动的尝试，以及下一行动。纯文档等任务无运行入口时写不适用，不另建入口。无后续工作时明确本次范围交付完成；有外部缺口时明确是规范就绪、局部通过或实际任务未闭环。仅在用户要求或确需继续执行时保留下一任务，不自行创造产品、永久监控或发布流程。

项目搬移、多根归属、接管、产物未写完、能力变化与资源耗尽按 [执行边界](execution-boundaries.md) 处理；原有测试失败按 [验收归因规则](verification.md) 处理。规则与工具静态交付、所选软件运行证据、实际产品验收分别闭环；不以全软件重跑作为每次任务的前提。
