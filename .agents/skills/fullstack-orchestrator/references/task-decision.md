# 任务决策：阶段、执行者、写入范围与结束证据

先决定本次需要做什么，再按既有协议执行。决策不增加授权，不改变交接状态机，不要求每次启用所有软件。任务模式和执行者路线分开记录；软件选择遵守调用项目规则及用户最新指令。

## 六个独立维度与最小记录

1. **意图/类型**：新建、接管、体验、功能、缺陷、性能、重构、升级、数据、安全、AI/算法、测试、运维、恢复、文档或分析；可以多标签。
2. **执行模式**：下表七模式之一；AUTO 明确实际选用策略，混合任务组合阶段，不堆叠整套流程。
3. **项目事实**：空/已有项目、运行/停止/未知、健康/故障/未知分别记录，可同时成立；核对实际根目录、栈、命令、用户改动与候选身份。不为画像启动/停止服务。
4. **影响/风险**：拟改模块/文件、接口/事件、数据、配置和消费者；**可写范围与需验证范围分开**。源码只改一处，也可能需要跨模块验证。搜索未覆盖的依赖记为未知，不声称全量分析。
5. **能力/路线**：所需能力、执行软件、客户端/传输、模型、工具与实际权限分别核实；授权及能力满足后，再考虑交接成本、可用性和实测成本。
6. **状态/证据**：任务、尝试、候选、产物和集成证据使用现有协议，不以模式代替生命周期或验收层级。

在对话或项目原生检查点简记：`意图；task_mode；事实/基线；可写范围；验证范围；启用/跳过阶段及理由；executor_route/允许回退；未决事项；验收与停止条件`。一行补丁可用一两句，复杂依赖才增加交付物依赖图与写入归属。无需新建 schema、完整 PRD 或必选代理。`task_mode=AUTO` 与 `executor_route=AUTO` 不是同一字段。

## 决策顺序与范围冲突

先解析有效指令和已有授权 → 核对原尝试及资源归属 → 判断影响和必要阶段 → 选满足约束的执行者 → 确定写入/验证及交付证据。软件偏好不能反向扩大范围；同一来源下，用户最新明确任务选择覆盖较早默认，独占约束不能被 AUTO 绕过；不同来源冲突按宿主指令层级处理。

“达成目标所必需”不是突破明确文件/模块限制的授权。比如只允许改 CSS，却发现问题来自服务端权限，继续只读定位并说明冲突、请求最小范围调整；不得伪装成样式修复修改鉴权。没有显式窄限制时，Main 可在原目标授权内调整常规兼容实现，但需更新影响和验证记录。

写入范围包括构建缓存、生成代码、锁文件、快照、测试报告、测试数据库及远端副作用，不只包括源码 diff。扩大验证范围不会自动授予这些写入权限；优先使用已有证据、真正只读方法或已授权隔离环境，仍无法满足必要验证时报告缺口。用户要求不写任何文件时，不得自行把临时目录当作例外。

## 七种共享核心模式

| 模式 | 选择及执行策略 | 结束证据/权限边界 |
|---|---|---|
| AUTO | 未指定策略时，根据事实选择下列模式和必要阶段 | 解释实际选择；实质歧义才询问 |
| GOAL | 已确认的完整复杂目标，按可验证交付物拆依赖 | 预定需求与相关门禁满足即结束；不表示无限授权、无限循环或自动创建持久目标 |
| PATCH | 局部兼容修复/微调；缺陷先定位根因 | 当前候选差异、受影响行为与必要依赖回归；不顺手重写 |
| FEATURE | 增量能力，先确定消费者/权限/数据契约 | 新流程及受影响旧流程，不强制设计或新后端 |
| REVIEW | 只读分析；允许只读代理，不派发修复 | 对话报告证据、风险与覆盖限制；默认不写源码、任务文件或自动创建 shared/。用户要求文件报告时只写获准报告范围 |
| UPGRADE | 核对当前/目标版本、兼容性、迁移及恢复路径 | 升级前后同口径检查、实际差异和兼容限制；不批量升级无关依赖 |
| RECOVER | 先核对运行版本、原尝试、源码变化和外部副作用 | 授权内恢复后的相关验证、保留现场和未决副作用；回退代码不能撤销消息、支付或数据演进 |

REVIEW 中测试、构建、包管理器和网络请求也可能写文件、修改数据库或触发服务行为；检查实际副作用后再运行。不能因命令叫检查就认定只读。模式切换不扩大授权：审查发现缺陷仅报告，已有修复授权才可转 PATCH。

## 选择最小阶段和必要证据

| 任务族 | 优先阶段 | 仅在影响成立时追加/必要证据 |
|---|---|---|
| 新建/项目接管 | 需求和现状、架构/契约、必要实现 | 设计/前后端/数据按产品需要；接管不等于重建；验收真实用户流程 |
| UI/体验 | 现有设计系统、受影响页面/状态、前端 | 新视觉探索才调用 Stitch；接口/权限变化才扩展依赖；验证视口、交互、可访问性及相关请求 |
| 功能/通信/API | 生产者、消费者、契约、实现 | 认证、错误、重试/幂等、流式等按协议需要；真实双方验证不能以 Mock 代替 |
| 缺陷/性能 | 复现/工作负载、定位、最小修复 | 相关回归；性能需同口径前后数据，未复现或未测不能声称解决 |
| 重构/技术栈升级 | 保持行为、调用者、版本/兼容边界 | 影响的构建、运行和契约回归；迁移与回退不能覆盖用户后来修改 |
| 数据/安全 | 目标环境、数据/对象权限、约束 | 备份可恢复性、迁移/拒绝路径和数据一致性；破坏性操作另获授权 |
| AI/算法 | 数据/模型/提示身份、评估协议 | 质量、安全、失败降级和实际成本；合成/Mock/离线证据分别声明 |
| 测试/交付/运维 | 目标候选、环境、现有命令、授权 | 区分构建、部署、健康及业务验收；恢复先协调副作用，不以健康检查替代业务 |
| 文档/分析 | 源码核实、明确输出范围 | 文档不修改运行行为；发现无关缺陷列出，不自动修复 |

混合任务取必要阶段的并集，合并重复验证。设计、契约或实现依赖未满足时只暂停依赖节点，继续独立授权工作。没有必要的阶段标 NOT_APPLICABLE 并简述理由；不能把未测试阶段标为已通过。

## 前端动态选择与默认调整

通用核心支持 Codex、Gemini Desktop、已获准的 Antigravity 或 AI Studio 等能力候选；**候选不等于已连接或已获准**。先解析调用项目的默认、动态候选、独占和暂停规则，再选择。当前仓库授权见 [project-policy.md](project-policy.md)。

- 用户指定执行端/独占路线优先。未指定且没有具体改选理由时沿用当前默认；默认不是独占。
- 常规工程 PATCH、已有设计实现、表单/状态/API 接线、紧耦合跨模块修复、构建/测试或重构，若 Codex 已有相关源码与工具、减少交接且满足任务能力和权限，可直接选 Codex，不要求 Gemini 先失败。有必要的视觉探索仍独立选择 Stitch/获准设计能力。
- 需要明显视觉探索、比较候选，或用户偏好 Gemini，且其所需能力和权限实际可用时，保留 Gemini 路线。模型品牌比较不能替代任务证据；不为比较软件重复开发同一功能。
- Gemini BUSY、不可用或交接代价明显过高时，可选任务已允许的 Codex 路线。运行或 UNKNOWN 的原尝试先核对完成、取消和副作用；不得在同一范围重复派发，不通过换客户端绕过访问限制。切换保留原证据、新尝试 ID、相同验收和受控写入范围。
- **本次改选不修改长期默认**。连续同类任务有实际质量、返工、延迟/交接成本证据时，可建议按任务族调整默认；取得项目既有维护授权或用户明确决定后才更新持久项目规则。不能因一次失败改全局配置、启用暂停软件或扩大上传权限。

在既有记录中保留选择/跳过原因、当前能力证据、原任务核对结果和验收责任。节省调用是决策因素；没有实际计量时 token/费用为 UNKNOWN，不宣称更便宜或质量更高。

## 有界自适应与结束

修改决策规则时按 [任务决策评测](decision-evaluation.md) 验证受影响场景，区分规则推演和实际软件执行；不为普通任务加载整个评测集。

新证据扩大影响时，只重评受影响的范围、依赖、路线和检查；常规授权内调整由 Main 决定，业务重大取舍、越权或不可逆操作才询问。保护用户差异，不无限重规划；同问题修复轮数和停止规则沿用 [handoff.md](handoff.md)。

完成需将必要需求映射到当前候选证据。必要检查失败/阻塞/未测就保留限定结论；不能用另一层 PASS 抵消。满足预定验收即交付；无关优化列为后续建议。长任务沿用项目 ADR、契约、检查点和历史证据，只在身份、环境、输入或影响改变时重验相关部分；不建立第二份真相或个人记忆。
